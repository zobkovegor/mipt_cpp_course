# Условие задачи: Шаблонный класс CircularBuffer

## Общее описание

Необходимо реализовать шаблонный класс `CircularBuffer`, представляющий циклический буфер с интерфейсом, аналогичным `deque` (быстрая вставка и удаление с обоих концов), но с фиксированной вместимостью, заданной при создании. Буфер должен поддерживать два различных случая в зависимости от того, известна ли вместимость во время компиляции или определяется в рантайме. Реализация должна избегать дублирования кода для этих случаев.

---

## Шаблонные параметры

Класс `CircularBuffer` имеет два шаблонных аргумента:
- `typename T` — тип хранимых значений.
- `std::size_t Capacity = DYNAMIC_CAPACITY`, где `DYNAMIC_CAPACITY` равно `std::numeric_limits<std::size_t>::max()`.

### Поведение в зависимости от `Capacity`

1. **Если `Capacity == DYNAMIC_CAPACITY`**:
   - Буфер аллоцируется в динамической памяти.
   - Вместимость хранится как поле и определяется в рантайме.

2. **Если `Capacity != DYNAMIC_CAPACITY`**:
   - Буфер создаётся на стеке, без аллокации динамической памяти.
   - Вместимость не хранится как поле (используется значение из шаблонного параметра).

**Примечание**: Реализация не должна содержать копипасту для этих двух случаев.

**Ограничение**: Использование стандартных контейнеров, кроме `std::array`, запрещено. Можно использовать `std::span` при необходимости.

---

## Итераторы

Класс должен предоставлять следующие типы итераторов:
- `iterator` — неконстантный итератор.
- `const_iterator` — константный итератор (не позволяет изменять элементы).
- `reverse_iterator` — неконстантный реверс-итератор.
- `const_reverse_iterator` — константный реверс-итератор.

### Требования к `iterator`

`iterator` должен поддерживать:
1. Инкремент (`++`) и декремент (`--`).
2. Сложение с целыми числами (`it + n`, `n + it`).
3. Сравнение: `<`, `>`, `<=`, `>=`, `==`, `!=`.
4. Разность двух итераторов (`it1 - it2`).
5. Разыменование (`*it`), возвращающее `T&`.
6. Оператор `->`, возвращающий `T*`.

### Требования к `const_iterator`

- Аналогичен `iterator`, но не позволяет изменять элементы.
- Допускается неявная конверсия `iterator` в `const_iterator`, обратная конверсия запрещена.
- Реализация `const_iterator` не должна быть копипастой `iterator`.

### Общие требования к итераторам

- Если `Capacity != DYNAMIC_CAPACITY`, итераторы не должны хранить вместимость буфера как поле.
- Итераторы не должны хранить указатель на объект `CircularBuffer`.
- Разыменование итератора должно требовать только одного разыменования указателя.

## Методы и конструкторы

### Общие предположения
- Вместимость буфера всегда положительна (случай нулевой вместимости обрабатывать не требуется).

### Конструкторы

1. **Если `Capacity == DYNAMIC_CAPACITY`**:
   - Конструктор, принимающий `std::size_t capacity` (вместимость).
   - Конструктор по умолчанию отсутствует (не компилируется).
   - Пример:
     ```cpp
     CircularBuffer<int> buffer1{32}; // OK
     CircularBuffer<int> buffer2{};   // Ошибка компиляции
     ```
   - Конструктор копирования от другого буфера того же типа.
   - Оператор присваивания от другого буфера того же типа.

2. **Если `Capacity != DYNAMIC_CAPACITY`**:
   - Конструктор по умолчанию (вместимость задаётся шаблонным параметром `Capacity`).
   - Конструктор, принимающий `std::size_t capacity`:
     - Если `capacity == Capacity`, создаётся буфер.
     - Если `capacity != Capacity`, выбрасывается исключение `std::invalid_argument`.
   - Пример:
     ```cpp
     CircularBuffer<int, 32> buffer1{};    // OK
     CircularBuffer<int, 32> buffer2{32};  // OK
     CircularBuffer<int, 32> buffer3{42};  // std::invalid_argument
     ```
   - Конструктор копирования от другого буфера с той же вместимостью.
   - Оператор присваивания от другого буфера с той же вместимостью.
   - Пример:
     ```cpp
     CircularBuffer<int, 32> buffer1{};
     CircularBuffer<int, 32> buffer2{buffer1}; // OK
     CircularBuffer<int, 42> buffer3{buffer1}; // Ошибка компиляции
     buffer1 = buffer2; // OK
     buffer1 = buffer3; // Ошибка компиляции
     ```

### Методы

- **Добавление элементов**:
  - `push_back(const T&)` — добавляет элемент в конец за `O(1)`.
  - `push_front(const T&)` — добавляет элемент в начало за `O(1)`.
  - Если буфер полон, затирается краевой элемент:
    - Для `push_back` — первый элемент.
    - Для `push_front` — последний элемент.

- **Удаление элементов**:
  - `pop_back()` — удаляет последний элемент за `O(1)`.
  - `pop_front()` — удаляет первый элемент за `O(1)`.

- **Информация о состоянии**:
  - `size()` — возвращает текущее количество элементов.
  - `capacity()` — возвращает вместимость буфера.
  - `empty()` — возвращает `true`, если буфер пуст.
  - `full()` — возвращает `true`, если буфер полностью заполнен.

- **Доступ к элементам**:
  - `operator[](std::size_t)` — доступ по индексу без проверки границ за `O(1)`.
  - `at(std::size_t)` — доступ по индексу с проверкой границ (выбрасывает `std::out_of_range`) за `O(1)`.

- **Итераторы**:
  - `begin()`, `cbegin()` — возвращают итератор/константный итератор на начало.
  - `end()`, `cend()` — возвращают итератор/константный итератор на элемент после конца.
  - Для константного буфера `begin()` и `end()` возвращают константные итераторы.
  - Декремент `end` возвращает итератор на последний элемент.
  - Вычитание целых чисел из `end` корректно возвращает итераторы на соответствующие элементы.
  - `rbegin()`, `crbegin()`, `rend()`, `crend()` — реверс-итераторы.

- **Обмен**:
  - `swap(CircularBuffer&)` — обменивает содержимое с другим буфером того же типа.
  - Если `Capacity == DYNAMIC_CAPACITY`, существующие итераторы должны продолжать указывать на те же элементы после `swap`.

- **Вставка и удаление**:
  - `insert(iterator, const T&)` — вставляет элемент перед позицией итератора за линейное время.
    - Элементы правее сдвигаются вправо.
    - Если буфер полон, затирается первый элемент.
    - Если буфер полон и итератор указывает на первый элемент, вставка не выполняется.
  - `erase(iterator)` — удаляет элемент по итератору за линейное время.
    - Элементы правее сдвигаются влево.

---

## Исключения

- Все методы, кроме `insert` и `erase`, должны быть строго безопасными относительно исключений:
  - В случае исключения в конструкторе или операторе присваивания типа `T` буфер возвращается в исходное состояние, а исключение пробрасывается выше.
- Если `Capacity != DYNAMIC_CAPACITY`, методы `operator=` и `swap` также могут не быть строго безопасными относительно исключений.
