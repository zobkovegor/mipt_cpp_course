# Условие задачи: Реализация StackAllocator и List с использованием аллокаторов

## Общее описание

Задача состоит из двух частей. Цель — научиться использовать аллокаторы, разобраться с устройством контейнера `list` и показать, что нестандартный аллокатор может дать выигрыш в производительности по сравнению со стандартным аллокатором.

---

## Часть 1: Класс StackAllocator

### Описание

Необходимо реализовать класс `StackAllocator<typename T, size_t N>` для создания стандартных контейнеров на стеке без обращений к динамической памяти. Для этого нужно также реализовать вспомогательный класс `StackStorage<size_t N>`, содержащий большой массив на стеке.

- **`StackStorage<size_t N>`**:
  - Хранит массив на стеке размером `N` байт.
  - Не поддерживает копирование.

- **`StackAllocator<typename T, size_t N>`**:
  - Легковесный, легко копируется и присваивается.
  - Должен быть STL-совместимым и удовлетворять требованиям [Allocator](https://en.cppreference.com/w/cpp/named_req/Allocator).

### Требования к `StackAllocator`

- **Методы и типы**:
  - Конструктор копирования, деструктор, оператор присваивания.
  - Методы `allocate` и `deallocate`.
  - Внутренний тип `value_type`.
  - Метод `select_on_container_copy_construction`, если это требуется логикой аллокатора.
- **Сравнение**:
  - Аллокаторы, построенные на разных `StackStorage`, считаются неравными.
- **Выравнивание**:
  - Объекты типа `int` должны размещаться по адресам, кратным 4.
  - Объекты типа `double` — по адресам, кратным 8, и т.д.
- **Производительность**:
  - Использование контейнеров с `StackAllocator` не должно вызывать обращений к динамической памяти.
# Условие задачи: Реализация класса List с использованием аллокатора

## Часть 2: Класс List

### Описание

Необходимо реализовать класс `List<T, Allocator = std::allocator<T>>` — двусвязный список, который корректно использует аллокатор и удовлетворяет требованиям [AllocatorAwareContainer](https://en.cppreference.com/w/cpp/named_req/AllocatorAwareContainer).

---

### Требования к `List`

- **Шаблонные параметры**:
  - `T` — тип элементов.
  - `Allocator` — тип аллокатора (по умолчанию `std::allocator<T>`).

- **Конструкторы**:
  - Без параметров.
  - От одного числа (`size_t`) — создаёт список заданного размера.
  - От числа и `const T&` — создаёт список заданного размера с элементами, равными переданному значению.
  - От одного аллокатора.
  - От числа и аллокатора.
  - От числа, `const T&` и аллокатора.
  - Если создаётся пустой список, выделения памяти не происходит, независимо от используемого аллокатора.

- **Методы**:
  - `get_allocator()` — возвращает текущий объект аллокатора.
  - `size()` — возвращает размер списка за `O(1)`.
  - `empty()` — проверяет, пуст ли список.
  - `push_back`, `push_front`, `pop_back`, `pop_front` — добавление и удаление элементов с обоих концов.
  - `insert(iterator, const T&)` — вставка элемента перед указанной позицией.
  - `erase(iterator)` — удаление элемента по итератору.

- **Итераторы**:
  - Двунаправленные итераторы, удовлетворяющие требованиям [BidirectionalIterator](https://en.cppreference.com/w/cpp/named_req/BidirectionalIterator).
  - Поддержка константных и реверс-итераторов.
  - Методы: `begin`, `end`, `cbegin`, `cend`, `rbegin`, `rend`, `crbegin`, `crend`.

- **Конструктор копирования, деструктор, оператор присваивания**:
  - Должны быть реализованы с учётом аллокатора.

- **Оптимизация памяти**:
  - Если аллокатор — тривиальная структура без полей, он не должен увеличивать `sizeof` объекта списка (занимает 0 байт).

- **Безопасность исключений**:
  - Все методы должны быть строго безопасны относительно исключений.
  - При выбросе исключения из методов класса `T` (кроме деструктора) список возвращается в исходное состояние, избегая UB и утечек памяти, и пробрасывает исключение выше.
  - Предполагается, что конструкторы и операторы присваивания аллокаторов не выбрасывают исключений (согласно требованиям к `Allocator`).
