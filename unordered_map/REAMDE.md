# Условие задачи: Реализация класса UnorderedMap

## Общее описание

Необходимо реализовать шаблонный класс `UnorderedMap<Key, Value, Hash, Equal, Alloc>` — упрощённый аналог `std::unordered_map`. Для реализации должен использоваться ранее написанный класс `List`, при этом использование `std::list` запрещено. Класс должен корректно поддерживать итераторы, аллокаторы и move-семантику. Все вспомогательные классы (например, `List`) также должны поддерживать move-семантику, и её нужно добавить в `List`, если она отсутствует.

---

## Описание класса

Класс `UnorderedMap<Key, Value, Hash, Equal, Alloc>` имеет следующие шаблонные параметры:
- `Key` — тип ключа.
- `Value` — тип значения.
- `Hash` — хеш-функция (по умолчанию `std::hash<Key>`).
- `Equal` — сравниватель (по умолчанию `std::equal_to<Key>`).
- `Alloc` — аллокатор (по умолчанию `std::allocator<std::pair<const Key, Value>>`).

### Требования к типам `Key` и `Value`

- Не обязаны иметь конструкторы по умолчанию, копирующий конструктор или копирующий оператор присваивания.
- Для работы с `UnorderedMap` достаточно наличия move-конструктора и move-оператора присваивания.

### Внутренний тип

- Публично определённый тип `NodeType` как `std::pair<const Key, Value>` (аналог `value_type` в `std::unordered_map`).

---

## Требования к функциональности

### Конструкторы и операторы

- Конструкторы (включая копирования и перемещения).
- Деструктор.
- Копирующий и перемещающий операторы присваивания.

### Доступ к элементам

- Метод `operator[]`:
  - Доступен только для неконстантных объектов.
  - Работает в среднем за `O(1)`.
  - Если ключ отсутствует, создаёт `Value` по умолчанию.
  - При передаче rvalue-ключа (если ключа нет) создаёт узел с перемещением, а не копированием.
- Метод `at(key)`:
  - Работает в среднем за `O(1)`.
  - Если ключ отсутствует, выбрасывает исключение.

### Информация о состоянии

- Метод `size()`:
  - Возвращает текущее количество элементов за `O(1)`.
- Метод `empty()`:
  - Проверяет, пуст ли контейнер.

### Итераторы

- Внутренние типы `iterator` и `const_iterator`, удовлетворяющие требованиям [ForwardIterator](https://en.cppreference.com/w/cpp/named_req/ForwardIterator).
  - Разыменование `const_iterator` не позволяет изменять элементы.
- Методы: `begin()`, `end()`, `cbegin()`, `cend()`.
- Итераторы должны:
  - Позволять пройтись по всем элементам за линейное время от их количества (а не от размера хеш-таблицы).
  - Инкрементация выполняется за гарантированное `O(1)`.

### Вставка элементов

- Метод `insert(const NodeType&)`:
  - Принимает ссылку на `NodeType`.
  - Возвращает `std::pair<iterator, bool>`:
    - `bool` — произошла ли вставка.
    - `iterator` — указывает на элемент с данным ключом (существующий или вставленный).
  - Эффективно обрабатывает lvalue и rvalue (перемещает, если передан rvalue).
  - Работает за `O(1)` в среднем.
- Метод `insert(InputIterator first, InputIterator last)`:
  - Вставляет диапазон элементов `[first, last)`.
  - Учитывает, что разыменование `InputIterator` может возвращать rvalue (например, для `std::move_iterator`).
  - Вставляет элементы перемещением, если переданы rvalue.
- Метод `emplace(Args&&... args)`:
  - Конструирует `NodeType` из переданных аргументов без копирования (если возможно).
  - Вставляет полученный объект в контейнер без копирования (если возможно).
  - Возвращает `std::pair<iterator, bool>` (как `insert`).
  - Работает за `O(1)` в среднем.

### Удаление элементов

- Метод `erase(iterator)`:
  - Удаляет элемент по итератору.
  - Работает за `O(1)` в среднем.
- Метод `erase(iterator first, iterator last)`:
  - Удаляет диапазон элементов `[first, last)`.
- Итераторы на неудалённые элементы не должны инвалидироваться.

### Поиск

- Метод `find(const Key&)`:
  - Возвращает итератор на элемент с заданным ключом или `end()`, если элемент не найден.
  - Работает в среднем за `O(1)`.

### Управление хеш-таблицей

- Метод `reserve(size_t)`:
  - Резервирует место под заданное количество элементов.
- Метод `load_factor()`:
  - Возвращает текущий коэффициент загрузки.
- Метод `max_load_factor()`:
  - Возвращает или задаёт максимальный коэффициент загрузки.

### Обмен

- Метод `swap(UnorderedMap&)`:
  - Обменивает содержимое с другим `UnorderedMap`.
  - Работает за `O(1)`.
  - Итераторы не должны инвалидироваться и продолжают указывать на те же элементы.

### Стабильность указателей

- Вставка и удаление элементов не должны инвалидировать указатели и ссылки на остальные элементы (`NodeType`).
- Вставка может инвалидировать итераторы, если происходит rehash.

---

## Требования к безопасности исключений

- Методы `insert` и `emplace` (для одиночных элементов) должны быть строго безопасны относительно исключений, кроме случаев, когда исключение выбрасывает хеш-функция.
  - При выбросе исключения состояние контейнера должно остаться неизменным.

---

## Поддержка аллокаторов

- `UnorderedMap` должен быть allocator-aware контейнером, удовлетворяющим требованиям [AllocatorAwareContainer](https://en.cppreference.com/w/cpp/named_req/AllocatorAwareContainer).
- Все операции с памятью должны выполняться через `allocator_traits`, без прямых вызовов `new`/`delete`.
- При конструировании и присваивании должны корректно использоваться методы аллокатора:
  - `select_on_container_copy_construction`.
  - `propagate_on_container_copy_assignment`.
  - `propagate_on_container_move_assignment`.
  - `propagate_on_container_swap`.

### Оптимизация памяти

- Если `Alloc`, `Hash` или `Equal` — тривиальные структуры без полей, они не должны увеличивать `sizeof` объекта `UnorderedMap` (занимают 0 байт).
